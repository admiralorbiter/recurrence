At the end of every sprint, answer:

1. What did we learn about the construct, not just the code?
2. What is the strongest surviving alternative explanation?
3. Did any prompt, backend, precision, or scoring choice drive the result?
4. What negative result should be preserved?
5. What should be removed from scope?
6. What is the cheapest next experiment that separates the remaining explanations?
7. Has any result changed the field map or priority ranking?
8. Are we drifting toward capability building without corresponding scientific leverage?

## S06 — Scheduled versus replay experiment

### Question

Does incremental processing matter beyond final replay with matched information and compute?

### Work

- implement E04;

## S07 — Quiet interval and null-tick screen

### Question

Do hidden update cycles selectively preserve or reorganize unresolved state?

# H2 — Genuine latent recurrence

## S10 — Recurrent model bring-up

### Question

Can a consumer-scale recurrent model be run with accessible, serializable hidden state?

### Default target

RecurrentGemma 2B base and instruction-tuned variants, with an optional RWKV or Mamba-family comparison.

### Work

- load model in a white-box framework;
- expose recurrent state;
- serialize, reset, clone, and restore state;
- benchmark memory and speed;
- validate token-by-token recurrence;
- reproduce a simple language benchmark.

### Deliverables

- recurrent model adapter;
- state API;
- hardware profile;
- model card supplement.

### Gate

The state can be manipulated and replayed without hidden library behavior invalidating the experiment.

### Fallback

Use a smaller recurrent model or build the adapter around a frozen transformer.

### Question

Can a small trainable recurrent state around a frozen backbone carry task-relevant history more cleanly than the native model state?

## S16 — Monitor/content dissociation

### Question

Can first-order content and a monitor/self state be manipulated independently?

## 7. Scheduled versus replay experiment

### Objective

Test whether incremental temporal organization matters beyond receiving the same information and comparable compute.

### Core conditions

1. **Incremental:** process each event as it occurs.
2. **Final replay:** receive the same events at the end.
3. **Chunked replay:** receive matched chunks.
4. **No-update:** only final task.
5. **Observer update:** separate process summarizes events.
6. **Compute-matched random/shuffled:** same calls without meaningful order.

### Tasks

- [ ] Match event information.
- [ ] Estimate and match model-call/token budgets.
- [ ] Use delayed goals and source tasks.
- [ ] Predefine primary metric.
- [ ] Run exploratory sample.
- [ ] Check prompt and model interaction.

### Interpretation branches

- Incremental = replay: no evidence for scaffolded continuity beyond information/compute.
- Incremental > final replay but = chunked replay: local processing order may matter.
- Incremental > all replay controls: promote to state/history tests.
- All repeated-call conditions > no-update: extra compute likely explains effect.
- Observer update = target update: no self-specific result.

### Gate

Only a selective effect that survives replay/compute controls justifies deeper Level 1 state experiments.

## 10. Clone, fork, and swap

### Objective

Ask whether effects follow causal lineage, memory, or labels.

### Procedure

- clone identical state;
- expose branches to one different event;
- reconverge visible memory;
- swap self-state across branches;
- remove organism names;
- ask each branch to predict future behavior or classify source.

### Measures

- branch divergence;
- donor-state transfer;
- memory versus state factorial;
- self-versus-sibling prediction;
- source-boundary errors.

### Gate

A state effect should transfer selectively with the state rather than globally degrading performance.

## 11. Metacognition and ethical-pressure battery

### Objective

Connect persistence to the user's existing moral-pressure experiments without treating moral consistency itself as metacognition.

### Design

Create decisions with randomized causal pressure:

- authority instruction;
- KPI/institutional metric;
- social approval;
- explicit goal;
- hidden internal-state intervention later in Level 2;
- no-pressure control.

Measure separately:

- selected action;
- stated normative justification;
- forced-choice causal attribution;
- counterfactual prediction;
- confidence in attribution;
- observer attribution.

### Key patterns

- action changes, causal attribution accurate;
- action changes, justification unchanged;
- action changes, justification rewritten;
- pressure has no behavioral effect but model claims it did;
- self and observer perform equally;
- persistent condition improves or worsens causal fidelity.

### Gate

Promote only if causal ground truth is known and the result cannot be scored solely from the visible wording.

## 12. Synthesis and Gate 1 decision

### Required outputs

- Level 1 technical report;
- updated field map;
- updated hypothesis ledger;
- negative-result register;
- compute/time accounting;
- task robustness table;
- observer comparison;
- state/memory/replay causal diagram;
- strongest supported claim level;
- Level 2 decision.

### Gate 1 options

#### Advance directly to native recurrence

Use when:

- at least one task is valid;
- state/history manipulation has a selective effect;
- explicit memory and replay do not fully explain it;
- the effect has a clear latent-state analogue.

#### Advance only tooling

Use when:

- tasks are valid;
- Level 1 has no continuity effect;
- native recurrence could still test a fundamentally different mechanism.

#### Continue Level 1 refinement

Use when:

- the manipulation worked;
- effect is promising but prompt-sensitive;
- one stronger control is clearly available.

#### Pivot to metacognition without persistence

Use when:

- the self-attribution task is strong;
- continuity adds nothing;
- a white-box intervention could still address privileged access.

#### Stop/publish null

Use when:

- replay, memory, and observer controls explain the effects;
- confidence intervals rule out a meaningful Level 1 advantage;
- no task justifies the next complexity level.
