In plain English

Memory can help without being recurrence. H1 asks whether carrying explicit state through time adds anything that cannot be reproduced from the external record.

The Question

What would persistence have to add beyond a very good notebook?

A normal language-model call can be treated as an episode: text goes in, text comes out, and the hidden activations used for that generation are not ordinarily carried into the next independent call.

The boundary H1 tries to draw

Level 1Public state

Transcript, JSON state, goals, provenance labels, summaries. Inspectable and reconstructible.

Level 2Latent recurrence

Persistent hidden state that can carry history unavailable to a prompt-only observer.

The key H1 question is therefore not “does memory help?” Of course memory helps.

Does carrying an explicit state through time produce a causal dependency that cannot be reduced to rereading, replaying, or reconstructing an external record?

The strong boring explanation

H1 treats ordinary external memory as a scientific control. If the transcript already explains the behavior, recurrence does not receive credit. If a deterministic reducer can rebuild the terminal state from history, the project does not call the resulting state irreducibly continuous.

What would count against H1’s stronger hopes?

  • Raw history matches or beats structured state.
  • State maintenance works only when the updater is deterministic.
  • Online maintenance can be replayed later.
  • Quiet reflection adds noise rather than selective consolidation.
  • Changing visible state has little effect when history disagrees.
  • “Self” judgments can be reconstructed from public role cues.
  • A matched observer predicts target errors as well as Self-framing.

H1 ended up seeing many of those outcomes. That is exactly why it becomes useful.
